# 01 — 打通一条命令备出一个文件

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 从空仓库起步，交付一条真正能把 PostgreSQL 备份成文件的命令。使用者手写一份配置文件，敲一条带数据源名的备份命令，磁盘上就出现一个带时间戳的 SQL 产物；备份失败时命令以非零码退出。这一票的重点是把整条路径打通并**确立 `runBackup` 这个唯一的测试接缝**——后续所有票都在同一个接缝上扩展测试，不再新增接缝。

本票不含：原子写入与校验、保留清理、状态记录、系统通知、终端界面、数据源管理命令。配置文件此时靠手写。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 仓库可通过 `bun link` 注册为全局命令 `mgdb`，在任意目录下可执行
- [ ] 仓库根目录可运行测试与类型检查，且全部通过
- [ ] 从用户配置目录下的配置文件中读取指定名字的数据源；配置文件缺失或数据源不存在时，报出可读的错误并以非零码退出
- [ ] 连接串被解析出主机、端口、用户名、数据库名；端口缺省时按 5432 处理
- [ ] 数据库密码经环境变量传给备份子进程，**不出现在子进程的命令行参数中**
- [ ] 备份工具按「配置指定目录 → 环境变量路径 → 常见安装位置探测」的顺序定位；找不到时错误信息说明原因与解决办法，而不是透出底层的可执行文件缺失错误码
- [ ] 子进程带上不携带属主与权限信息的参数执行
- [ ] 产物文件名为「数据源名 + 精确到秒的时间戳 + 扩展名」，同一天多次执行不会相互覆盖
- [ ] 子进程退出码非零时，命令判定为失败并以非零码退出
- [ ] 存在 `runBackup` 测试接缝，注入「执行备份子进程」与「取当前时间」两个 port
- [ ] 测试通过替换这两个 port 验证上述行为，**不接触任何真实数据库**；文件系统用真实的临时目录
- [ ] 测试断言假子进程实际收到的主机、端口、用户名、数据库名与密码环境变量
