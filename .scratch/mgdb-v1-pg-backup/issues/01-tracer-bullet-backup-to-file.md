# 01 — 打通一条命令备出一个文件

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 从空仓库起步，交付一条真正能把 PostgreSQL 备份成文件的命令。使用者手写一份配置文件，敲一条带数据源名的备份命令，磁盘上就出现一个带时间戳的 SQL 产物；备份失败时命令以非零码退出。这一票的重点是把整条路径打通并**确立 `runBackup` 这个主测试接缝**。

本票不含：原子写入与校验、保留清理、状态记录、系统通知、终端界面、数据源管理命令。配置文件此时靠手写。

**Blocked by:** None — can start immediately

**Status:** 已完成

- [x] 仓库可通过 `bun link` 注册为全局命令 `mgdb`，在任意目录下可执行
- [x] 仓库根目录可运行测试与类型检查，且全部通过
- [x] 从用户配置目录下的配置文件中读取指定名字的数据源；配置文件缺失或数据源不存在时，报出可读的错误并以非零码退出
- [x] 连接串被解析出主机、端口、用户名、数据库名；端口缺省时按 5432 处理
- [x] 数据库密码经环境变量传给备份子进程，**不出现在子进程的命令行参数中**
- [x] 备份工具的定位：**配置了 `pgBinDir` 就以它为准，找不到即报错、不回退 PATH**；没配才走环境变量路径 → 常见安装位置探测。找不到时错误信息说明原因与解决办法，而不是透出底层的可执行文件缺失错误码
      （票面原写的是三级回退。改成「显式配置即权威」，因为显式配置被环境里碰巧存在的另一版本悄悄顶替时，「跑的不是我配的那个」最难排查）
- [x] 子进程带上不携带属主与权限信息的参数执行
- [x] 产物文件名为「**数据库名** + 精确到秒的时间戳 + 扩展名」，同一天多次执行不会相互覆盖
      （票面原写的是数据源名。改用数据库名，因为数据源名是可随时改的标签，拿它当前缀意味着改一次名字，此前所有备份就从计数和清理里消失）
- [x] 子进程退出码非零时，命令判定为失败并以非零码退出
- [x] 存在 `runBackup` 测试接缝，注入「执行备份子进程」与「取当前时间」两个 port
- [x] 测试通过替换这两个 port 验证上述行为，**不接触任何真实数据库**；文件系统用真实的临时目录
- [x] 测试断言假子进程实际收到的主机、端口、用户名、数据库名与密码环境变量

**实现结果**：主接缝确实是 `runBackup`，但「不再新增接缝」没做到——最终有 5 个，
每个都在对应测试文件顶部写了理由，spec 的「实际用到的其他接缝」一节有汇总。
