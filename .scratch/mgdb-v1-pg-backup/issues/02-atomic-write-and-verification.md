# 02 — 原子写入 + 格式感知校验 + 格式可选

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 让一次失败的备份不可能留下一个看起来合格的残缺产物。备份先写入临时文件，通过格式感知的完整性校验后才原子就位；任何环节失败（子进程非零退出、校验不通过、使用者按下 Ctrl-C）都会清理临时文件，且已有的历史产物分毫不动。

同时引入第二种备份格式。两种格式必须同时存在，因为校验判据本身是随格式分派的——只有一种格式就测不了这个分派。

**Blocked by:** 01 — 打通一条命令备出一个文件

**Status:** ready-for-agent

- [ ] 备份先写入临时文件，校验通过后才原子重命名为正式产物
- [ ] 支持纯 SQL 与自定义（压缩）两种格式，可用命令行参数单次指定；未指定时取配置的默认值，默认为纯 SQL
- [ ] 纯 SQL 产物的校验要求文件尾部带有完整的结束标记
- [ ] 自定义格式产物的校验要求其内部目录能被完整列出
- [ ] 校验不通过时：删除临时文件、不产生正式产物、以非零码退出，且错误信息能区分「子进程失败」与「产物校验失败」
- [ ] 子进程失败时同样清理临时文件，目录中不留任何残余
- [ ] 执行中按 Ctrl-C 中断时清理临时文件，已存在的历史产物不受任何影响
- [ ] 临时文件的命名不会被后续的清理逻辑或「最新」指针误认为正式产物
- [ ] 测试覆盖：合格产物通过校验、截断产物被拒、两种格式各自走对校验分支
- [ ] 测试覆盖：让假子进程失败后，断言目录中不存在任何新增文件
