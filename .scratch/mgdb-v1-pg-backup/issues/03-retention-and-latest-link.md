# 03 — 保留清理 + latest 符号链接

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 让备份目录的磁盘占用有一个硬上限。每次备份**成功后**删除超出保留份数的最旧产物，并维护一个指向该数据源最新产物的固定名字，这样引用「最新那份」不必先去查时间戳。

这是整个工具里唯一会销毁数据的代码，所以清理范围被严格限死：只有文件名符合本工具命名规则**且**属于当前数据源的文件才进入候选集。备份目录很可能被设成下载目录这类混杂目录，这条约束保证别的文件绝对安全。

**Blocked by:** 02 — 原子写入 + 格式感知校验 + 格式可选

**Status:** ready-for-agent

- [ ] 备份成功后自动删除超出保留份数的最旧产物
- [ ] 保留份数按数据源独立计数，可在全局默认值与单个数据源上分别配置，默认 14
- [ ] 保留份数配置为 0 时不执行任何删除
- [ ] 清理只影响文件名符合本工具命名规则、且属于当前数据源的文件；目录中的其他文件与其他数据源的产物一律不动
- [ ] 清理**绝不**扫描整个目录做模式匹配删除
- [ ] 备份失败时不执行清理（不能出现既没有新备份、又丢了旧备份的情况）
- [ ] 每个数据源有一个指向其最新产物的符号链接，清理后重新指向仍然存在的最新文件，不留悬空链接
- [ ] 符号链接既不计入保留份数，也不会被清理删除
- [ ] 删除发生时打印被删文件的清单，删除动作可见而非静默
- [ ] 计算待删列表的逻辑写成纯函数：输入候选文件列表与保留份数，输出待删列表
- [ ] 测试覆盖：往临时目录预置一批文件（含不合命名规则的杂文件、其他数据源的产物、符号链接），跑一次备份后断言哪些被删、哪些存活
- [ ] 测试覆盖：不足保留份数、正好等于保留份数、保留份数为 0、备份失败四种情形下均不误删
