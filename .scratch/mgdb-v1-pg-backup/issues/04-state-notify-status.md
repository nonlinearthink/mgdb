# 04 — 状态记录 + 失败通知 + status 命令

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 解决「备份失败了但我不知道」这个备份系统最经典的死法。每次备份的结果被持久记录，失败时主动弹 macOS 系统通知推给使用者，另有一条命令可以随时查看每个数据源的备份健康状况。

这一票引入第三个 port（发送系统通知）。前两个 port 在 01 号票中确立，通知 port 到这里才需要，不提前预留。

**Blocked by:** 02 — 原子写入 + 格式感知校验 + 格式可选

**Status:** 已完成

- [x] 每次备份（无论成败）将结果写入状态文件：本次运行时间、上次成功时间、本次成败、失败原因、产物路径与体积
- [x] 备份失败时经通知 port 发送 macOS 系统通知
- [x] 通知 port 可注入，测试中不会真的弹出系统通知
- [x] `status` 命令列出每个数据源的上次成功备份时间、现有份数、占用空间
- [x] `status` 命令支持机器可读的输出格式，便于将来被其他脚本消费
- [x] 从未备份过的数据源在 `status` 中有明确显示，而不是空白或报错
- [x] 状态文件缺失或内容损坏时，`status` 与备份命令都不崩溃，按「无历史记录」处理
- [x] 状态写不进去时作为警告上报，**成功与失败两条路径都要报**——失败时状态没记上，面板会继续显示上一次成功、状态正常，直到超期天数到了才标红
- [x] 失败时的错误信息包含足够定位问题的上下文：哪个数据源、哪一步、底层报了什么
- [x] 备份失败时进程以非零码退出
- [x] 测试覆盖：成功一次后状态文件内容正确；假子进程失败后状态记为失败、通知 port 被调用、退出码非零
