# 09 — 移除 manygames 旧备份脚本

**Spec:** `docs/specs/2026-08-16-mgdb-v1-pg-backup-design.md`

**What to build:** 让 manygames 仓库里只剩下一条备份路径。两条并存的后果是两套命名规则、两个可能不同的输出目录、以及半年后无法确定「到底哪个才是真正在跑的那个」——而这种不确定性恰恰会在最需要备份的那天暴露。

**这一票原本不能在新工具刚跑通的当天执行。** spec 要求先并行验证一段时间，所以「已完成足够的并行运行」被写成了本票的第一条验收条件。**实际执行时使用者明确决定跳过这条**——理由见下方验收条件里的说明。

**Blocked by:** 03 — 保留清理；04 — 状态记录 + 失败通知 + status 命令；07 — Ink：备份流程

**实现结果**：旧备份功能的四处改动**全都是未提交的工作**——`scripts/backup.ts`
从未被 git 跟踪，`.gitignore` / `.env.example` / `package.json` 的相关改动也都停在
工作区。所以「移除」不是一次删除加提交，而是把工作区还原到 HEAD：那个状态里
本来就没有旧脚本。执行后 manygames 工作区干净，`db` 包的 typecheck / test / check 全过。

**遗留一件事**：`packages/db/.env`（被 gitignore，且项目 AGENTS.md 禁止读写）里
可能还留着 `DB_BACKUP_PATH` 这一行。它现在没有任何代码会读，留着无害，但要清
得由使用者自己动手。
